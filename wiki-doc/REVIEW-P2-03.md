# Проверка выполнения P2-03 — 2026-09-19

Проверены план, статус, изменения предыдущей сессии и путь
SQL → inventory → plan → facts → Markdown → gate. Исходное заявление о завершении
P2-03 не подтверждалось: положительный полный цикл примера 12 не работал,
а обязательные по плану оракул и мутации отсутствовали. Замечания исправлены.
P2-04 и P2-05 остаются не начатыми; их реализация не входит в эту проверку.

## Найдено и исправлено

1. **Положительный цикл был заблокирован.** Каталог DDL отвергал ALTER ADD CONSTRAINT
   из примера 12 как неупорядоченную миграцию. Теперь добавление ограничений после
   CREATE той же таблицы в одном файле использует порядок операторов. Для изменений
   из разных файлов по-прежнему нужен manifest; PK обновляет свойства колонок.
   USING INDEX явно блокируется до разрешения колонок готового индекса.
2. **Gate не связывал новые правила с фактами.** TRIGGER/INDEX/GRANT/REVOKE уже
   входили в список проверяемых операций, но `trigger/index/constraint/access_rule`
   не могли удовлетворить проверку `fact_ids`. Теперь требуется ссылка на найденную
   по исходнику операцию, как для обычного `operation`.
3. **Структурные детали не доходили до фактов.** Адаптер и gate сохраняли/проверяли
   DDL, но пропускали отдельные поля расширений. Теперь timing/events, выражения и
   WHERE индекса, ограничения, привилегии и роли входят в `operations.structure`
   и сверяются с AST. Согласованная подмена фактов и текста не получает ready.
4. **AST мог заменяться неполным regex-результатом.** Для новых конструкций и
   ограничений такой переход отключён. Fallback при ошибке AST остаётся диагностикой
   с блокирующим пробелом анализа.
5. **Ограничения CREATE TABLE не имели обязательств.** Извлекаются ограничения
   таблицы и колонок; каждое получает отдельную проверку. Используются имена enum
   pglast, а не числовая карта типов. Полный DDL сохраняет дополнительные модификаторы.
6. **Сохранялась утечка области при выборе одной функции.** Автономные конструкции
   выбранной таблицы больше не добавляются к функции. Поддержана привязка расширений
   к view/materialized view/CTAS; неоднозначная привязка оставляет coverage note.
7. **Права извлекались с потерями.** Исправлены тип объекта через enum, PUBLIC,
   колоночные привилегии и grant option. Неподдержанные цели GRANT (schema, routines,
   ALL ... IN SCHEMA) явно блокируют анализ.
   `GRANT ALL (column)` сохраняет ALL, а не null.
8. **Отсутствовал версионированный контракт расширения.** Оболочки артефактов
   сохраняют v2; новые структуры используют `extension_version: 1`.
   Схемы inventory/facts проверяют версию и структуру, facts требует поля новых операций.
9. **Не было сквозной приёмки.** Добавлены `expected/12`, запись в `cases.json`,
   восемь предметных мутаций в двух режимах и тесты согласованного удаления операций
   и ограничений. Проверки наличия примера больше не используют skip.
10. **Тесты зависели от окружения.** Subprocess-тесты импортируют `publish` из
    явного рабочего каталога scripts; проверка Markdown-ссылок использует pathlib
    и не требует установленного rg. Исправлена устаревшая инструкция о legacy gate.

## Границы результата

Регрессия использует детерминированный reference/saved адаптер; это не три запуска
LLM writer. Для примера 12 дополнительно просмотрены SQL, поля фактов и видимые
структуры Markdown. Автоматическая проверка произвольного свободного текста
не заявляется. Исходный SQL не выполнялся в БД.

Нулевой false-ready относится к размеченным мутациям. Новые требования схем
и хэши кода требуют повторной сборки старых комплектов с расширениями;
прошлые решения не переносятся автоматически. Поддержка всех диалектов, любых
вариантов ALTER/GRANT и разрешение отсутствующих определений не заявляются.
