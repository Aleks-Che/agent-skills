# Повторная проверка P2-04 — матрица диалектов

Дата: 2026-09-19. Требования: [IMPLEMENTATION-PLAN.md](IMPLEMENTATION-PLAN.md),
P2-04 и REVIEW §8.4. Проверены актуальная матрица, код анализаторов, SQL примеров,
выбор документируемых объектов, тесты и передача инструкций изолированному адаптеру.
Предыдущие незакоммиченные изменения сохранены и уточнены.

## Найденные расхождения и исправления

| Замечание | Исправление и подтверждение |
|---|---|
| Матрица создавала впечатление отдельной поддержки Greenplum; код допускает только `postgres`/`postgresql` | Явно описан отказ `dialect=greenplum`. Сценарий 11 подтверждает одну страницу `audit_probe`, профиль `CKR_GP` и `{"name":"postgres","version":"unknown"}`; добавлен положительный build/gate-тест |
| Заголовок «Проверенные версии» смешивал метаданные `version: 15` с проверкой серверной версии | Указаны статический характер проверки и фактическая грамматика pglast 7.14: `(17, 7)`. Серверы PostgreSQL/Greenplum не запускались; `version` не переключает парсер |
| Необоснованная привязка конструкций к сценариям и обобщение unit-тестов до полной поддержки | В 04 нет UPDATE FROM/DELETE USING, в 13 нет индекса, в 11 нет GRANT/REVOKE; ветвление/присваивания подтверждает 05. Матрица ссылается на конкретные тесты и различает инвентарь/полный цикл; PROCEDURE, CALL и grant option больше не объявлены автоматически проверенными |
| Неразобранный EXECUTE ошибочно разрешался как честный `unknown` | Разделены неизвестное runtime-имя при разобранном шаблоне и неразобранное выражение. Второе блокирует gate; добавлен сквозной отрицательный тест `EXECUTE p_sql` |
| «Greenplum-специфичные конструкции не парсятся» обещало больше, чем доказано | Отказ для DISTRIBUTED BY/RANDOMLY закреплён тестами. Остальные конструкции/опции обозначены непроверенными: принятие общей формы опций парсером не подтверждает их семантику |
| Отсутствовали существенные границы миграций, а тесты `regex_extract` не проверяли regex-путь и полный gate | Добавлено ограничение INDEX/TRIGGER/GRANT в migration manifest. Тесты переименованы, старый сканер вызывается напрямую; MySQL/MSSQL/Oracle/SQLite/greenplum/unknown проверены через AST, инвентарь, миграции и полный gate с отчётом `ok` |
| Изолированный адаптер не получал матрицу по ссылке из SKILL.md | `run_regression.isolate` копирует только `docs/dialect-support.md`; тест проверяет совпадение байтов и отсутствие tests/examples/history/ожидаемых результатов. Протокол регрессии обновлён |
| Полный набор выявил отказ конкурентного publisher на Windows: `Path escapes wiki: .wiki-doc/index.lock` | В `wiki_store.inside` устранено ложное различие обычной и расширенной (`\\?\`) записи разрешённого пути; сравнение сохраняет проверку выхода за корень и запись корня для последующих `relative_to`. Два теста моделируют локальные/UNC-пути и настоящий выход за границу; конкурентный тест ожидает завершения обоих процессов даже при ошибке |

Изменения не добавляют новый SQL-диалект и не расширяют грамматику анализатора.
В `test_sql_ast.py` добавлены шесть тестов к семи первоначальным тестам P2-04;
имеющиеся тесты усилены. Проверка изоляции расширена без увеличения числа методов.
Дополнительно добавлены два теста Windows-путей в `test_publish.py` для исправления
обнаруженной регрессии P1-07. До исправления проверка эквивалентных путей воспроизводила
четыре отказа; после исправления все шесть подслучаев и конкурентная публикация проходят.

## Воспроизведение

Команды выполняются из `wiki-doc/wiki-doc` с зависимостями из `requirements.txt`:

```text
python -B -m pytest tests/ -q -p no:cacheprovider
python -B scripts/run_regression.py --mode reference --output ../.runtime/p2-04-acceptance --repeats 3
python -B scripts/regression_mutations.py ../.runtime/p2-04-acceptance/regression-report.json --expected-root examples/expected --output ../.runtime/p2-04-acceptance-mutations
python -B scripts/regression_publish.py ../.runtime/p2-04-acceptance/regression-report.json --wiki ../.runtime/p2-04-acceptance-wiki
```

Для повторения нужны новые выходные каталоги. Интерпретатор проверки:
`C:/Users/Aleks/AppData/Local/Programs/Python/Python312/python.exe`, Python 3.12.7.
Python из PATH указывал на другое окружение с неполными зависимостями и не смог
собрать тесты; глобальные пакеты/настройки не менялись. Для skill-creator
`quick_validate.py` на Windows использован `-X utf8`.

Первый полный прогон не засчитан: изменение хешируемых инструкций во время его
выполнения вызвало отказы publisher. Промежуточный повтор остановлен после
обнаружения ошибки изоляции. Приёмка относится к отдельному прогону после всех
правок пакета, без изменения проверяемых файлов во время выполнения.
Сбой конкурентной публикации на следующем полном прогоне не списан на окружение:
внесены описанное исправление Windows-путей и детерминированные тесты. После этого
полный набор, reference-цикл, мутации и публикация запущены заново на новых комплектах.

## Границы приёмки

Поддержка SQL остаётся ограниченной [матрицей](wiki-doc/docs/dialect-support.md).
Reference-адаптер проверяет контролируемые утверждения по отдельным ожиданиям;
это полуавтоматический цикл, не полный LLM-прогон. Исполнение SQL на сервере
и общая совместимость с PostgreSQL/Greenplum не заявляются.

P2-05 (эксплуатация: общая CLI-обёртка, версия и остальные пункты плана) остаётся
не начатым; наличие отдельных CLI и publisher не означает выполнения этого этапа.
