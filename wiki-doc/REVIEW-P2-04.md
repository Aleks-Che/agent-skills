# Проверка выполнения P2-04 — 2026-09-19

Сверены план, статус и артефакты реализации. Подробно перепроверен последний
закрытый пункт P2-04 и сохранение регрессии предыдущих этапов. До исправлений
старый полный набор давал 652 passed, 1 skipped, 182 subtests passed, но новые
проверки выявили ошибочный допуск. P2-05 действительно не начат; реализация
эксплуатационной обёртки не входит в эту проверку.

## Найдено и исправлено

1. **MERGE в EXECUTE обходил контроль версии.** Полный комплект с константой
   или format получал `ready` / `publication_authorized=true` при версии `14`
   и `unknown`. Для прямого MERGE проверка существовала, для динамического
   шаблона — нет. `Analyzer.check_merge_version` теперь используется в обоих
   путях. После исправления эти случаи дают `blocked` с причиной
   `analysis gap: MERGE requires a confirmed PostgreSQL version >= 15`.
   Положительные случаи версии 15 и неизвестной версии без MERGE сохранены.
2. **Отрицательные тесты gate проверяли ошибку схемы.** Они вручную добавляли
   coverage_note с полями `line` и `severity`, без обязательного `source_ref`.
   Gate отказывал на JSON Schema, не доходя до проверки диалекта/версии.
   Тест unknown MERGE вообще использовал SQL без MERGE. Теперь тесты создают
   настоящие SQL и корректные артефакты, требуют точную причину отказа и
   `input_error=false`; проверяют также восстановление удалённой диагностики.
3. **Тест чистого разбора проверял только метаданные.** Добавлены проверки
   объявления и отсутствия coverage_notes для каждого из 12 примеров.
   Для GP проверяются обе конструкции: DISTRIBUTED BY и EXECUTE ON MASTER.
4. **Регистр имени диалекта различался между инвентарём и миграциями.**
   `PostgreSQL` принимался SQL-анализом, но давал `unsupported` в ddl.py.
   Миграционный manifest теперь использует ту же проверку без учёта регистра.
5. **Миграционные тесты меняли пакет.** Общее имя `_tmp_manifest.json` внутри
   examples создавало риск столкновения параллельных запусков и удаления чужого
   файла. Теперь каждый тест использует собственную временную копию данных.
6. **Матрица завышала гарантии.** «Полная» поддержка и «Любая» версия заменены
   точными границами 25 групп конструкций. Исправлены ссылки: IF/INTO — пример 05,
   ALTER ADD CONSTRAINT и GRANT/REVOKE — 12. Добавлены предметные тесты для
   PROCEDURE/CALL, materialized view, постоянного EXECUTE и COMMENT в миграциях.
   Разделены отказ для dialect=greenplum и применение профиля CKR_GP;
   устранено необоснованное утверждение о специальной блокировке pg_stat_*.
   Для COMMENT и динамического SQL явно ограничены гарантии извлечения.
7. **Матрица терялась в runtime-копии и не входила в хэш инструкций.**
   `run_regression.isolate` копировал инструкции со ссылкой на docs/dialect-support.md,
   но сам документ отсутствовал. Теперь он копируется отдельно от исторического
   обзора и включён в `skill_md_sha256`. Существующие тесты изоляции и контрольных
   сумм расширены: до исправления оба падали, после него проходят.
8. **Следующий шаг в статусе устарел.** В конце файла оставался P2-04, несмотря
   на его закрытие в начале. План и статус согласованы: следующий пункт P2-05.

## Воспроизведение

Из каталога пакета `wiki-doc/wiki-doc`, с Python 3.12 и зависимостями requirements.txt:

```text
python -B -m pytest tests -q -p no:cacheprovider
python -B scripts/run_regression.py --mode reference --output <new_workspace> --repeats 3
python -B scripts/run_regression.py --mode saved --output <same_workspace> --repeats 3
python -B scripts/regression_mutations.py <workspace>/regression-report.json --expected-root examples/expected --output <new_mutation_dir>
python -B scripts/regression_publish.py <workspace>/regression-report.json --wiki <new_isolated_wiki>
```

В текущей среде использован напрямую установленный Python 3.12:
`C:/Users/Aleks/AppData/Local/Programs/Python/Python312/python.exe`.
Launcher `py -3.12` под sandbox-пользователем не обнаружил установку, а Python
из PATH использовал venv с недоступным импортом MarkdownIt. После выбора
интерпретатора закреплённые зависимости загрузились; установки и изменения
глобальных настроек не потребовались. `PYTHONDONTWRITEBYTECODE=1` передан дочерним
процессам. Существовавшие до проверки изменения отслеживаемых pyc сохранены.

## Границы результата

Регрессия reference/saved полуавтоматическая; полный LLM-цикл не запускался.
SQL разбирался статически, без БД. Нулевой false-ready относится к размеченному
набору и добавленным регрессиям MERGE. Отсутствие проверки минимальной версии
прочих конструкций не является доказательством совместимости с сервером.

Изменение кода меняет хэши tooling в manifest. Старые решения нельзя переносить
на изменённый пакет без повторной сборки и проверки комплекта.
