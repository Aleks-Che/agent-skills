## Исправления

1. **Миграция q08 не соответствовала oracle.** Один ADD COLUMN оставлял порядок
   `id, legacy, total, amount`, хотя ожидалось `id, amount, legacy, total`.
   Синтетическая миграция теперь действительно переставляет колонки через
   DROP/ADD. Тест восстанавливает manifest и сверяет порядок, типы, default,
   comment и позиционный SELECT. SQL в БД не исполняется.
2. **q09 выдумывал конкретные KPI.** SQL фильтровал только struct_id, поэтому
   KPI 10/20 не следовали из него. Добавлены явные условия kpi_id; наборы уровней
   теперь различаются: 10/100 — 1,2; 20/200 — 1. Тест сверяет каждую тройку
   KPI/структура/уровень и её формулу. Три расчётные ветви не означают три строки
   данных: количество строк зависит от входных таблиц.
3. **q03 не проверял два флага.** Вместо is_done/is_phoned использовались IN и
   избыточный NOT IN по непересекающимся наборам. Теперь два независимых флага
   вычисляются по пересекающимся наборам 5/3 кодов. Контрпример содержит две
   строки: приоритет выбирает более позднюю задачу; её флаги различаются.
4. **Матрица D12 была подменена.** Неизвестная расшифровка RR не воспроизводит
   заявленную совместимость СУБД из исходного ревью. Добавлено q05-A5:
   `version=unknown` не доказывает PostgreSQL >=9.4 / Greenplum >=5.
   Итого 35 blocking-утверждений (ранее фактически 34, а не заявленные 33).
   Полная проверка мутаций результата writer
   остаётся Q-07; наличие JSON-утверждений не выдаётся за её прохождение.
5. **Ошибки legacy теряли смысл.** Введён `SubjectSelectionError`, подкласс
   ValueError, для отсутствующего/неоднозначного `--subjects`. Другие ошибки
   анализа сохраняются как blocking coverage notes. При успешном AST нативные
   операции остаются, но неожиданный отказ вспомогательного сканирования
   больше не исчезает, включая перехваченный внутри операции ValueError.
   Ограничения legacy для поддержанных AST-конструкций не отменяют успех AST;
   проверен выбор quoted identifiers. Ошибки входа сохраняют код CLI 2.
6. **DDL-диагностика указывала на другой файл.** Заметки теперь ссылаются на
   исходный контекстный DDL, его SHA-256 и диапазон строк. Они сохраняются и
   без DECLARATION в основном SQL. Неверная кодировка остаётся ошибкой входа.
7. **Часть тестов не выполняла заявленные проверки.** Поиск слов в исходнике
   gate заменён настоящим готовым комплектом, подменой SQL, удалением заметок,
   пересчётом evidence/manifest и вызовом gate. Отказ проверяется именно по
   `analysis gap`, с `input_error=false`. CLI-тесты требуют код 0 и inventory,
   а не принимают любой код 2. Изоляция проверяется реальным `isolate()` для
   всех 11 случаев и составом скопированных файлов. Это изоляция переданных
   артефактов, не ограничение доступа произвольного процесса ко всему диску.
8. **Планы и статусы противоречили друг другу.** В основных файлах исправлено
   «Q-этап не начат». Приёмка старой сохранённой страницы относится к Q-01,
   новый LLM-результат — к Q-08. Исторические результаты отделены от текущих.
   Битая ссылка на отсутствующий REVIEW-P0-01.md заменена явным указанием
   отсутствующего исторического отчёта; его содержимое не выдумывается.
