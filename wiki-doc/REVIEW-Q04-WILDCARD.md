План выполнен частично: историческая приёмка P0–P2 сохраняется в её заявленных

## Замечания и исправления

| Проблема | Воспроизведение и исправление |
|---|---|
| Частичные CTE aliascolnames обрезали проекцию | `WITH c(a) AS (SELECT id,x FROM demo.t) SELECT * FROM c` возвращал только `a`. Теперь получаются `a,x`, в исходном порядке |
| Aliascolnames считались доказанным составом при неизвестной ширине SELECT | `c(a) AS (SELECT * FROM demo.missing)` преждевременно раскрывал внешний wildcard. Теперь нужны установленные выходы; избыток имён тоже не создаёт выдуманные колонки |
| Позиционный INSERT через derived мог взять одноимённую физическую таблицу | `SELECT * FROM (SELECT id,x FROM demo.t) d` при наличии каталожного `d(wrong)` возвращал `wrong`. AST-проход теперь разрешает локальные источники отдельно, включая неизвестные проекции |
| Derived-алиас попадал в наследуемое пространство CTE | Случаи `WITH d ... FROM (SELECT * FROM d) d` и `FROM d c CROSS JOIN (...) d` смешивали разные источники. Derived-ссылки теперь принадлежат конкретному FROM; квалифицированная `demo.t` также не подменяется CTE `"demo.t"` |
| Вложенные derived-выходы не были связаны с проекцией подзапроса | Сохранён `result_for` на фактическом результате подзапроса. Цепочка `SELECT * FROM (SELECT * FROM (SELECT * FROM demo.t) a) b` раскрывается как `b.id,b.x` |
| Итерация останавливалась после 10 проходов или при неизменном числе unresolved-операций | Завершение теперь определяется отсутствием раскрытых wildcard. Проверена цепочка из 15 CTE; каждый успешный проход уменьшает число wildcard |
| Полный build с CTE падал с `KeyError: source_ref` | В каталог CTE/derived сохраняется доказательство исходника. Положительный `build+gate` теперь проходит; неизвестная ширина, избыток имён и вложенный JOIN USING остаются заблокированными |
| Текущие сводки расходились по числу gaps и описанию реализации | Синхронизированы IMPLEMENTATION-PLAN/STATUS, Q-статус, SQL-support и CHANGELOG. Предыдущий completion-review явно помечен историческим |

Правило позиционного переименования сверено с документацией
[PostgreSQL: Table Aliases](https://www.postgresql.org/docs/13/queries-table-expressions.html#QUERIES-TABLE-ALIASES).
Полная поддержка FROM column aliases, JOIN USING/NATURAL, recursive CTE,
set-operation projections и вывода типов выражений этим изменением не заявляется.

Изменены `scripts/sql_ast.py` и `scripts/sql_types.py`; добавлены
[15 регрессионных тестов](wiki-doc/tests/test_q04_wildcard_review.py).
Первоначальные 13 тестов на неисправленном коде дали 13 failures и одну ошибку
(с учётом подслучаев); после исправлений добавлены отрицательные full-gate
контроли и проверка отсутствия утечки имён между операторами.
