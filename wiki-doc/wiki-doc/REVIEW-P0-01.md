# Проверка и исправление P0-01

Дата: 2026-09-12. Основание: [IMPLEMENTATION-PLAN.md](../IMPLEMENTATION-PLAN.md), P0-01.

## Результат

Первоначальная реализация не закрывала критерии связности и надёжного отказа,
несмотря на успешные 39 тестов. После исправлений P0-01 принят в границах проверки
формы и объявленных связей. Полный допуск ready, независимое извлечение SQL и
проверка фактических файловых доказательств ещё относятся к P0-02…P0-05.

## Подтверждённые дефекты и исправления

| Дефект до исправления | Наблюдение | Исправление |
|---|---|---|
| Неполный комплект считался полным | Пустой каталог возвращал отсутствие ошибок | Все семь артефактов обязательны по умолчанию; частичный этап задаётся явно через --artifacts |
| Битые внутренние ссылки | Несуществующие documented_object_ids и writes принимались | Типизированные ссылки объектов, операций, колонок, условий, формул и unknown проверяются; ID уникальны между категориями |
| Неполная межфайловая проверка | Дубли checks и другой page_id принимались | Проверяются ID проверок/плана, inventory anchors, plan_check_id, ссылки decision, пути manifest и page_id |
| Ошибка типа приводила к падению | objects[0].id = [] вызывал TypeError: unhashable type | При ошибке схемы проверка связности не запускается; возвращается диагностика поля |
| Формат времени фактически не проверялся | created_at = "not a timestamp" принимался | Включён FormatChecker, зафиксирована зависимость rfc3339-validator; отсутствие checker даёт ошибку установки |
| Не вся заявленная функциональность была доступна | Схема migration_manifest не участвовала в CLI; зависимости не были закреплены | Отдельный режим --migration-manifest, requirements.txt с проверенными версиями |
| Схемы и инструкции расходились | Валидатор генерировал отчёт без v2-метаданных; единая строка type_evidence не различала два типа | Согласованы writer/validator, форма v2, отдельные доказательства типов, ссылки и правила перехода |
| Недостаточные отрицательные тесты | Тесты проверяли главным образом форму и отдельные helper-функции | Добавлены реальные комплекты, 49 регрессионных тестов с мутациями и вызовами CLI |

Дополнительно: проверяются непустые значения ссылок, диапазоны строк, согласованность
объявленных source hashes, отсутствие повторных ключей JSON и NaN/Infinity.
Missing schema и ошибки чтения не игнорируются. Неиспользуемый common.schema.json
с устаревшими определениями удалён; остаются восемь входных схем.

Контракт допускает CTE/temp с областью видимости и корректные unknown. Переименование
ID факта не ломает независимую ссылку плана на inventory anchor. Контекстные объекты
не требуют полного покрытия на странице выбранной функции.

## Проверки

Из корня пакета выполнено:

```text
python -B -m unittest discover -s tests -q
```

Результат: **88 тестов, все прошли** (9 прежних тестов расчётчика + 30 исходных
тестов P0-01 + 49 регрессионных). Прогон включает положительный полный комплект,
частичную проверку, невалидные данные, повреждённые ссылки и отдельный CLI manifest
миграций. Входной SQL не исполнялся.

Обновлённые Markdown-ссылки проверены. Валидация скилла выполнена командой
`python -X utf8 -B <skill-creator>/scripts/quick_validate.py .`: `Skill is valid!`.
Первый запуск без -X utf8 упирался в локальную кодировку cp1251; повторный запуск
с явным UTF-8 прошёл. Проверяющий скрипт skill-creator не изменялся.

## Границы результата

`artifact_schema.py` всегда возвращает `publication_authorized: false`. Проверка
согласованности строковых хэшей не подтверждает существование файлов или их байты.
Существование section_id в Markdown, полнота SQL-инвентаря, обязательность результатов
плана, критичность дефектов и истинность текста не объявляются реализованными.

Старый validation_gate.py продолжает считать метрики отдельного отчёта и может
вернуть ready; он не является новым gate полного комплекта. Прежний ready нельзя
перенести в новый decision.json автоматически. Эти ограничения явно указаны в
инструкциях и [статусе](../IMPLEMENTATION-STATUS.md).

При переходе от первоначального варианта v2 нужно восстановить добавленные поля
и отдельные основания типов по исходникам; одной замены номера версии недостаточно.
Существующая пользовательская wiki и SQL не изменялись.
