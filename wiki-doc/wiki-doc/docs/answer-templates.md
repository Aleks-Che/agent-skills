# Шаблоны итогового ответа

Дата: 2026-09-19. Статус: часть P2-05.

Заполняйте шаблоны только подтверждёнными результатами pipeline. Неизвестные
значения отмечайте явно или опускайте. `page_id` уже содержит `.md`; повторно
добавлять расширение нельзя. `ready` означает допуск комплекта, а об успешной
публикации можно сообщить только после результата publisher `published=true`.

## 1. Успешная публикация

```text
Страница опубликована: <wiki>/<page_id>
Объект: <canonical_key>
Решение gate: ready
Проверено: <resolved>/<applicable> обязательств; дефекты: <defect>; unknown: <unknown>.
Источники: <проверенные пути SQL/DDL>.
Индекс обновлён. <При idempotent=true: запуск уже был опубликован, дублей нет.>
Ограничения описания: <подтверждённые ограничения либо «нет выявленных»>.
```

Если получен только ready, пишите «Комплект готов к публикации» и указывайте
путь к черновику. Не представляйте допуск как уже совершённую запись.

## 2. Ревизия (revise)

```text
Страница не опубликована: <page_id>. Решение: revise.
Проверено: <resolved>/<applicable> обязательств.
Требуется исправить:
- <check_id>: <причина из отчёта и конкретное исправление>.
Черновик: <run_dir>/page.draft.md
Отчёт: <run_dir>/validation.json
```

## 3. Блокировка (blocked)

```text
Страница не опубликована: <page_id>. Решение: blocked.
Причины:
- <ошибка входа, неполнота анализа или блокирующая проверка>.
Следующее действие: <что нужно изменить для новой проверки>.
Черновик: <путь, если файл существует>.
```

## 4. Lint-отчёт

```text
Wiki: <wiki_root>
Lint: <valid=true/false>. Замечаний: <число issues>.
- <file>: <code> — <message>.
```

Строку файла, способ исправления и сводку актуальности добавляйте только при
наличии этих данных в lint/index/metrics. Не придумывайте номер строки или статус.

## 5. Query-ответ

```text
Запрос: <краткое описание вопроса>.
Найдено:
- <page_id> — <canonical_key>; <подтверждённая связь или свойство>.
Страница: <wiki>/<page_id>
Доказательства: <SQL-файл, диапазон строк из evidence>.
Ограничения: <неполнота данных, неопределённая цель или актуальность>.
```

## 6. Метрики

```text
Wiki: <wiki_root>. Снимок: <generated_at>.
Страницы: <pages.total>; управляемые: <pages.managed>; legacy: <pages.legacy>.
Источники: <sources.fresh>/<sources.total_tracked> актуальных.
Страниц с устаревшими источниками: <sources.outdated_pages>.
Покрытие: <coverage.resolved>/<coverage.resolved + coverage.unknown>;
дефекты: <coverage.defect>; unknown: <coverage.unknown>.
Решения: <checks.ready>/<checks.total_decisions> ready;
первая отметка ready: <checks.first_ready_at или «нет данных»>.
Ошибочные ready: <decision_accuracy.erroneous_ready>/<decision_accuracy.total_mutations_tested>.
Битые ссылки: <broken_links.total> в <broken_links.files_affected> файлах.
```

Это снимок опубликованной wiki и доступных архивных решений, не произвольный
временной интервал. При нулевом знаменателе доля не определена; отсутствие
мутационного отчёта не означает проверенное отсутствие ошибочных ready.

## 7. Публикация (dry-run)

```text
Предпросмотр публикации: <page_id из комплекта>.
Изменения:
- <путь из changes>: <краткое содержание diff либо «без изменений»>.
Файлы не изменены (dry-run).
```

`changes` содержит diff страницы, `index.md`, метаданных страницы, машинного
индекса и lineage. Число сохранённых ручных блоков API не возвращает.
Если команда отказала, сообщите причину отказа, а не успешный предпросмотр.

## 8. Ошибка

```text
Операция завершилась ошибкой: <сообщение команды>.
Этап: <известный этап>. Run ID: <известный run_id или «не определён»>.
Файл: <путь, если установлен>.
Следующее действие: <конкретный шаг по причине ошибки>.
```

Не объявляйте выполненным откат без подтверждения recovery. При конфликте
укажите сохранённые артефакты и необходимость разрешить конфликт.
