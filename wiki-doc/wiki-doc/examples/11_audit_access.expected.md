# 11 — вызов аудита и чтение audit-таблицы

Вход: 11_audit_access.sql, активный профиль CKR_GP. Документируем audit_probe().

- Прямой PERFORM ..._audit_gp_core.add_log('start') разрешён исключением для вызовов;
  прохождение через _apt не требуется.
- SELECT из ..._audit_gp_core.logs — отдельное чтение, не покрыто этим исключением.
- Отдельного основания прямого чтения _core в наборе нет: отметить отсутствие
  подтверждённого проектного исключения, не объявлять его разрешённым.
- Тело add_log известно, поэтому его запись в logs можно описать как эффект вызова,
  отличая её от прямого чтения audit_probe.
- Точное описание такого SQL может быть ready; замечание к исходному доступу само по
  себе не блокирует документацию и не разрешает менять SQL.
- Версия Greenplum не выводится из префикса схемы: unknown.
