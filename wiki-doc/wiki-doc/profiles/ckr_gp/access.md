# Правила доступа CKR_GP

Применяй только при активном [профиле CKR_GP](profile.md).
Это соглашения проекта, а не универсальные ограничения PostgreSQL/Greenplum.
Область витрины определяется полным идентификатором loader/витрины в проекте:
общий фрагмент kb_ckr не делает две разные витрины одной.

## Матрица межвитринного доступа

Колонки — слой **объекта назначения обращения**. Для вызовов audit действует
отдельное исключение ниже. Внутренние права СУБД здесь не выводятся из названий.

| Обращение | _ini | _stg / _mtd | _core | _apt |
|-----------|------|-------------|-------|------|
| BVD → собственная BVD | разрешено | разрешено | разрешено | разрешено |
| BVD → другая BVD | запрещено | запрещено | запрещено | запрещено |
| BVD → SVD | запрещено | запрещено | запрещено | запрещено |
| SVD → BVD | запрещено | запрещено | запрещено | разрешено |
| SVD → другая SVD | схема не предусмотрена | требуется подтверждение проектного исключения | требуется подтверждение проектного исключения | разрешено |

BVD обращается только к собственным схемам. Для SVD обычная точка межвитринного
чтения — _apt. Ограниченный доступ SVD → SVD через _core допускается по подтверждённому
соглашению проекта; не выдумывай согласование по одному SQL-вызову.
Собственные переходы SVD между слоями сверяй со схемой loader, а не с ограничениями
**между разными** витринами. При отсутствии такой схемы фиксируй неопределённость.

## Исключение: вызовы аудита

SVD может **напрямую вызывать функции/процедуры логирования** в схеме
`*_audit_gp_core`. Посредник _apt для такого вызова не требуется.

- `PERFORM <audit_schema_core>.add_log(...)` — прямой вызов функции аудита,
  разрешён указанным исключением.
- `CALL <audit_schema_core>.log_event(...)` — вызов процедуры при её наличии
  и поддержке выбранной версией СУБД.
- `SELECT * FROM <audit_schema_core>.logs` — чтение таблицы; исключение вызовов
  на него **не распространяется**. Требуется отдельное основание доступа.
- Чтение опубликованных данных аудита через _apt — обычный разрешённый SVD → SVD доступ.

Не применяй исключение к BVD или произвольной записи в audit-таблицы.
Неразрешённое обращение, которое действительно присутствует в SQL, документируй
точно и вынеси в замечания к исходному коду; не исправляй SQL в режиме документации.
