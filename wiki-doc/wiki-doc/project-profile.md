# Профиль CKR_GP

Активируй при явном указании CKR_GP пользователем/конфигурацией проекта либо
подтверждённых именах схем/loader с `s_gp_p1024_dmr_svd_` и
`s_gp_p1024_src_bvd_` в документируемом проекте. Для другого проекта не применять.
Сам факт присутствия этого файла в пакете скилла не подтверждает совпадение проекта.

## Диалект и версия

Диалект — PostgreSQL с Greenplum-расширениями, если это подтверждено проектом.
**Версия Greenplum в этом пакете не задана.** Найди её в конфигурации/документации
целевого проекта; иначе зафиксируй unknown. Не подставляй выдуманную версию.

Учитывай DISTRIBUTED BY, свойства хранения и EXECUTE ON MASTER только когда они
есть в исходнике и поддержка подтверждена версией проекта. Факт наличия конструкции
в SQL можно описать без заявления, что она исполнима на неизвестной версии.

В PostgreSQL MERGE доступен с версии 15:
[официальная документация PostgreSQL 15](https://www.postgresql.org/docs/15/sql-merge.html).
Из этого не следует поддержка MERGE какой-либо неизвестной версией Greenplum.
В PostgreSQL `now()` возвращает timestamptz; тип существующей цели определяется её DDL.

## Схемы и файлы

| Признак | Смысл |
|---------|-------|
| s_gp_p1024_dmr_svd_* | SVD |
| s_gp_p1024_src_bvd_* | BVD |
| _ini / _stg / _mtd / _core / _apt | Слои по соглашению проекта |
| gp/all/<loader>/ | Возможный корень SQL одного loader |
| 001create_table/<name>.sql | Быстрый кандидат определения; поиск изменений обязателен отдельно |

Для поиска loader можно сопоставить s_-схему с u_-директорией и суффиксом _loader.
Подтверди соответствие по проекту, не считай его обязательным для каждого объекта.
Матрица доступа и исключение аудита определены только в [rules.md](rules.md).

## Предметные конструкции

Применяй проверку только при наличии соответствующей конструкции в исходном SQL.

| Конструкция | Что объяснять |
|-------------|---------------|
| ckr_uup_queue | Реальные статусы, параметры очереди, fallback и обновление состояния |
| ckr_uup_products_contract_val | Условия исключения продуктов и область DELETE |
| ckr_uup_org_st | JOIN-ключи и обогащение оргструктурой |
| product_group | Значения групп именно из выражений SQL; одна группа может иметь несколько INSERT |
| coef_up | Все ветви расчёта, условия и места использования |
| consent и ROW_NUMBER | Полный порядок приоритетов и правила дедубликации |
| IF/WHERE с границами дат | Точные даты и включённость границ, независимо от имени переменной |
| init_type_oper / start_oper / add_log / end_oper | Фактическая последовательность аудита, включая обработчики ошибок |
| hist-таблицы | Реальный способ накопления истории, если он подтверждён кодом |

Не вставляй эти сущности в таблицу/view/функцию, где их нет.
Не задавай минимум числа INSERT, замечаний или секций. Применимость разделов
для всех типов объектов определяется [template.md](template.md).

## Оформление диаграммы

При подтверждённых слоях можно использовать цвета: STG — #fff3cd,
CORE актуальный — #d4edda, CORE история — #d1ecf1. Историческая роль подтверждается
логикой, а не только похожим именем. Добавь легенду при использовании цветов.
Это оформление не меняет фактические направления reads/writes/calls.
