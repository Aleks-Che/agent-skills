# Проверка покрытия Markdown

`scripts/coverage_gate.py` проверяет карту версии 2, область обязательных фактов,
секции, фрагменты и локальные ссылки. Модуль вызывается полным `validation_gate.py`
после независимого восстановления inventory/plan. Отдельный запуск проверяет только
покрытие и всегда возвращает `publication_authorized: false`.

```text
python scripts/coverage_gate.py --bundle <run_dir> --wiki-root <wiki_dir> --json
python scripts/validation_gate.py --bundle <run_dir> --root project <project_dir> --root wiki <wiki_dir> --write-decision --json
```

В bundle-режиме обязательны facts, coverage, validation_plan и page.draft.md.
При отдельных входах используй `coverage.json page.draft.md facts.json --plan <plan>`.
Без плана отдельная проверка выводит применимость секций из фактов и сообщает об
ограничении; это не независимая проверка SQL. Повреждённый или явно указанный
отсутствующий план/каталог правил не игнорируется. Коды CLI: 0 — покрытие проверено,
1 — дефект покрытия/ссылки, 2 — ошибка входа или зависимости.

## Секции и фрагменты

Стабильные section_id определены общим каталогом `references/check-policy.json`.
Используй ID в заголовке `## Формулы {#formulas_dependencies}` либо скрытый маркер
перед заголовком:

```markdown
<!-- wiki-doc:section formulas_dependencies -->
## Формулы и зависимости

<!-- wiki-doc:fragment total -->
Сумма рассчитывается как `sum(amount * 1.1)` при `amount > 0`.
```

Ссылка в coverage:

```json
{"section_id": "formulas_dependencies", "fragment_ref": "#total"}
```

`fragment_ref` ссылается на ID заголовка или скрытого фрагмента внутри указанной
секции. Для совместимости принимается ID без `#`. Без fragment_ref целевой фрагмент —
вся секция. Маркер `wiki-doc:fragment` закрепляет следующий абзац, список, таблицу
или блок кода; между ними допустимы пустые строки. Перепрыгивать через другой
заголовок или текст нельзя. Пустой/неизвестный ID и фрагмент из другой секции — ошибка.
Поддержан также отдельный `<a id="total"></a>`: перед заголовком он задаёт ID секции,
перед содержимым — ID фрагмента. Произвольный HTML преобразуй в Markdown.

Разбор использует [markdown-it-py](https://markdown-it-py.readthedocs.io/en/latest/using.html):
CommonMark, таблицы и зачёркивание. Учитываются ATX/Setext-заголовки, вложенные
подразделы, списки, таблицы, fenced/indented code и комментарии. Код может раскрывать
факт; заголовок, пустой блок, разделитель и скрытый комментарий не дают покрытия.
Подраздел входит в родительскую секцию до следующего заголовка того же/верхнего уровня.

Повторный явный ID секции/фрагмента отклоняется. Одинаковые видимые заголовки с разными
ID разрешены. Для обычных заголовков вычисляется lowercase-slug, повторения получают
`-1`, `-2`; для обязательных секций предпочитай явный стабильный ID. Коллизия явного и
вычисленного ID также отклоняется. Заголовки в цитатах/списках не объявляют секции страницы.

## Область и смысл проверки

Обязательны документируемые objects, их определения и предметные факты, а также
достижимые условия, формулы, колонки и unknown. Ссылка операции на внешнюю таблицу
не требует документировать все её колонки. Контекст вне области можно опустить;
если ссылка покрытия для него дана, она тоже проверяется.

Категории обязательных фактов и разрешённые секции берутся из `coverage` общего
каталога правил; применимость секций — из проверенного плана. Отдельного каталога
критичности модуль не вводит. Например, формулу нельзя покрыть секцией назначения.
Процент считает только обязательные факты с успешно разрешёнными ссылками; ошибочная
ссылка не засчитывается как покрытие. Результат содержит фактические диапазоны строк
в `fragments`, чтобы содержательный валидатор проверял именно указанный текст.

Непустота и правильный адрес фрагмента не доказывают истинность текста. Валидатор
сверяет каждый целевой фрагмент с фактом и SQL/DDL, связывает результат с fact_ids и
указывает доказательства. Искажение формулы/типа/зависимости — технический defect,
даже если структура покрытия верна. Регрессия P1-02 проверяет отказ gate при таком
содержательном результате. Независимая генерация и оценка всех 11 страниц — P1-04;
этот модуль не заменяет её и не распознаёт произвольную ложную фразу автоматически.

## Локальные ссылки

Путь будущей страницы — `<wiki_root>/<page_id>`, включая сохранённые вложенные пути.
От этого каталога разрешаются Markdown-ссылки, reference links и изображения.
Ссылка на саму будущую страницу проверяется по черновику, даже если файл ещё не
опубликован. Для относительных файловых ссылок wiki_root обязателен; каталог run
не подставляется вместо него.

Проверяются существование файла и ID Markdown-якоря. Для SQL/другого текстового файла
поддержаны якоря строк `#L3` и `#L3-L8`. URL-пути декодируются; выход за разрешённые
корни и абсолютные файловые ссылки отклоняются. Для ссылок на SQL вне wiki передай
`--link-root <project_dir>` в coverage CLI; полный gate использует `--root project`.
HTTP(S)/mailto-ссылки не запрашиваются по сети. Ссылки внутри кода и комментариев
не считаются ссылками страницы.

Полный gate повторно проверяет хэши прочитанных файлов ссылок в конце запуска.
При повторной проверке/архивировании передай тот же корень wiki; архив не копирует
все связанные страницы. Их актуальное существование и якоря проверяются заново.
При чтении архива SQL-доказательства используют `--root project <archive_dir>`,
а ссылки на исходный SQL-проект — `--root link_project <original_project_dir>`.
`bundle.save_bundle` сохраняет это различие при проверке создаваемой копии.
Это проверка разрешения ссылок, а не содержательная аттестация связанных страниц.
