# Идентичность SQL-объекта

Общий модуль — `scripts/identity.py`. Его используют экстрактор и полный gate.
Правила нормализации относятся к PostgreSQL. Неопределённая схема,
неоднозначный тип или неоднозначный реестр путей дают IdentityError и исключают допуск.

## Канонический ключ

- Таблица/view/materialized_view/ctas: `kind+schema+name`.
- Function/procedure: `kind+schema+name+(type1,type2,...)`; пустой список — `()`.
- Миграция: `migration+project/relative/path.sql+id`. Если ID не передан, используется
  числовой префикс имени файла, иначе имя без расширения. Установленный проектом ID
  передавай явно через --migration-id.

Сначала нормализуются компоненты, затем применяется UTF-8 percent encoding:
разделители `+`, `,`, скобки, кавычки и `%` внутри компонента экранируются. Поэтому
разные quoted identifiers с пунктуацией не могут слиться в один ключ.
Обычный ключ остаётся читаемым: `function+core+calc+(integer,boolean)`.

Имена без кавычек приводятся к нижнему регистру. В quoted identifiers сохраняются
регистр и символы, удвоенная кавычка означает одну кавычку. Имена длиннее 63 UTF-8
байт отклоняются: нестандартный NAMEDATALEN требует отдельной настройки алгоритма.
Схема обязательна; `public` и search_path не угадываются.

Для routine порядок входных типов значим. INOUT и VARIADIC входят в ключ;
OUT, имена параметров и DEFAULT исключаются. Типовые алиасы нормализуются
(`int4` → `integer`, `bool` → `boolean`), модификаторы типов и размеры массивов
не различают перегрузки. `float(p)` учитывает точность: 1–24 → real, 25–53 →
double precision. Схема пользовательского типа должна быть указана явно;
quoted типы сохраняют регистр. SQL `char`/`character` соответствует bpchar,
а каталоговый `"char"` — отдельный однобайтовый тип; они дают разные ключи.
Квалифицированные/quoted имена типов не превращаются в SQL-алиасы по написанию.
`serial` не подменяется integer как тип аргумента.

API/CLI без arg_types означает **известное отсутствие входных аргументов**,
а не неизвестную сигнатуру. Экстрактор не превращает неразобранную сигнатуру в `()`.
Полная исходная сигнатура (имена, OUT, DEFAULT, RETURNS) всё равно описывается в wiki;
канонический ключ служит для идентичности, а не заменяет это описание.

Основания: [CREATE FUNCTION](https://www.postgresql.org/docs/15/sql-createfunction.html),
[quoted identifiers](https://www.postgresql.org/docs/current/sql-syntax-lexical.html),
[float(p)](https://www.postgresql.org/docs/current/datatype-numeric.html),
[символьные типы](https://www.postgresql.org/docs/17/datatype-character.html).

## Имя страницы и существующие пути

Новое имя — `<slug>--<sha256-prefix>.md`. Slug ограничен 80 ASCII-символами;
суффикс начинается с 12 hex-символов SHA-256 от UTF-8 канонического ключа.
При занятом имени удлиняется только суффикс нового имени. Исчерпание 64 символов
даёт ошибку, а опубликованные страницы автоматически не переименовываются.

`identity.py compute --registry pages.json --legacy-keys old-keys.json ...` читает
две явные карты:

```json
{"manual/calc.md": "old-calc-key"}
```

```json
{"old-calc-key": "function+core+calc+(integer)"}
```

Однозначное совпадение текущего ключа или явного old → new сохраняет существующий
путь. Пути должны быть относительными Markdown-путями внутри wiki. Разделитель
нормализуется в `/`; выход за wiki, дубли нормализованных путей и несколько страниц
для одного ключа отклоняются. Реестр следует строить по фактическим метаданным wiki;
он не является разрешением произвольно приписывать существующим страницам ключи.

Для gate создай отдельный снимок обеих карт и передай его bundle create:

```json
{
  "pages": {"manual/calc.md": "old-calc-key"},
  "legacy_keys": {"old-calc-key": "function+core+calc+(integer)"}
}
```

`bundle.py create ... --identity-registry <snapshot.json>` фиксирует его путь/хэш.
Gate сверяет canonical_key с SQL, а page_id — с вычисленным именем или этим снимком.
Архив сохраняет снимок. `identity.py check <key> --existing-ids ...` возвращает
код 1 при занятом стандартном имени; compute может выбрать свободное расширенное имя.

Схема результата compute — `schemas/identity.schema.json`. AST-анализ P1 поддерживает
quoted identifiers в объявлениях; матрица синтаксиса и границы разрешения зависимостей —
[sql-support.md](sql-support.md). Неподдержанная конструкция сохраняет analysis_gap.
