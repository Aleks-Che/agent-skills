# Метрики качества

```text
python scripts/metrics.py <wiki> --json --regression-report <mutations>/mutation-report.json
```

Отчёт мутаций создаёт `scripts/regression_mutations.py`; полный порядок запуска —
[regression.md](regression.md). Положительный `regression-report.json` не подходит.
Команда метрик только читает wiki. Повреждённый архив, незавершённая публикация,
ошибка чтения или изменение wiki во время расчёта дают код 2 без успешной сводки.

Формат — [metrics.schema.json](../schemas/metrics.schema.json), версия 1.
`generated_at` задаёт время снимка; `period` явно задаёт область измерения.
Legacy-страницы учитываются в `pages.legacy`, но исключаются из долей по управляемым
страницам. Исторические версии страницы исключены: учитывается её текущая публикация.

| Метрика | Источник, знаменатель и период |
|---|---|
| `fresh_sources` | Доля текущих управляемых страниц, у которых все `tracked_inputs` совпадают с диском; общий механизм с Query |
| `full_coverage` | Доля текущих управляемых страниц, для которых `validate_coverage` подтверждает 100% покрытия фактов в текущем Markdown; процент завершённых проверок gate не заменяет эту проверку |
| `first_pass_success` | Доля текущих управляемых страниц, у которых первая наблюдаемая выдача решения в текущем `run_id` дала `ready` |
| `blocking_defects` | Блокирующие дефекты в решениях текущих опубликованных комплектов |
| `open_unknowns` | Все `facts.unknowns` и проверки со статусом `inconclusive` в текущих комплектах; ID имеют префиксы `fact:` и `check:` |
| `outdated_pages` | Число уникальных страниц с изменёнными, отсутствующими или недоступными источниками; несколько файлов одной страницы дают единицу |
| `broken_links` | Число `link_invalid` текущего Lint, включая legacy и индекс |
| `erroneous_ready` | Ошибочные `ready` / все размеченные результаты в переданном отчёте мутаций; период — этот прогон |
| `average_iterations` | Среднее `1 + число неуспешных выдач решения` по текущим опубликованным `run_id`; успешные перепроверки и попытки публикации не являются исправлениями |

Для долей с нулевым знаменателем `percent: null`. Отсутствующий/пустой отчёт,
пропущенная мутация или неисполненная проверка (`evaluated: false` / `error`) дают `erroneous_ready.measured: false`
и `percent: null`. Чужой формат, дубликаты и противоречие между `decision` и
`false_ready` отклоняются. Цель `percent = 0` проверяется только на измеренном прогоне.
Отказ схемы на намеренно повреждённом артефакте (`input_error: true`) является
результатом проверки и учитывается как отклонённая мутация.

## История проверок

Gate с `--write-decision` сохраняет `validation-history.json` внутри run для
идентифицированного валидным manifest комплекта, включая отклонённые проверки.
Выданное `decision.json` содержит снимок этой истории; publisher сохраняет его
в архиве вместе с решением. Повторные проверки без `--write-decision`, Lint,
Query, recovery и публикация не добавляют попытки.

История относится к одному `run_id`: исправляй комплект в том же run, а для
нового цикла создай новый ID. История служит измерению и не заменяет проверки допуска gate.
Проверки до появления валидного manifest не входят в период измерения.
`period.validation_start`/`validation_end` задают границы наблюдений.

Старое решение без истории не доказывает успех с первого раза. Если хотя бы у одной
текущей страницы нет полной истории, `first_pass_success.measured: false`,
`percent: null` и `average_iterations: null`; `measured_pages` и `unmeasured_pages`
показывают полноту наблюдений. Повторная выдача решения для старого run не восстанавливает
утраченные наблюдения и сохраняет `complete: false`.
При исправлении page_id внутри прежнего run история другой страницы также
не используется для утверждения об успехе с первого раза; сам gate проверяет
новую идентичность обычным способом.
