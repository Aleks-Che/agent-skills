# Статический анализ PostgreSQL

Зависимость: `pglast==7.14` (libpg_query), закреплена в `requirements.txt`.
Парсер разбирает PostgreSQL SQL и PL/pgSQL без подключения к БД. Совместимость
проверена на 13 случаях в [manifest](../examples/cases.json). Regex-сканер сохранён
для стабильных якорей прежнего простого поднабора; сначала всегда выполняется AST-разбор.
Ошибка AST не может разрешить публикацию через regex fallback.

| Конструкция | Поддержанный результат |
|---|---|
| FUNCTION / PROCEDURE | Идентичность, входные типы, имена/режимы/DEFAULT параметров, RETURNS, volatility |
| SELECT / PERFORM / CALL | Отдельные вхождения, reads/calls, выражения, фильтры |
| INSERT / UPDATE FROM / DELETE USING | Цель отдельно от источников, колонки INSERT, назначения UPDATE |
| MERGE, PostgreSQL ≥15 | USING как источник; условие сопоставления и отдельные ветви с назначениями |
| CTE / TEMP | Идентификатор с областью, локальная зависимость, определение, порядок, ON COMMIT |
| VIEW / MATERIALIZED VIEW / CTAS | Выходные имена и выражения; CTAS создаёт и заполняет цель |
| PL/pgSQL IF / ELSE / ASSIGN / INTO / RETURN | Условие, ветка, цель присваивания, переменные INTO, возвращаемое выражение |
| EXECUTE constant / format | Шаблон, аргументы, тип команды и статически видимые источники; runtime-имена неизвестны |
| CREATE / ALTER / DROP / RENAME / DEFAULT / COMMENT | Состояние таблиц по явному порядку, PK/NOT NULL и комментарии колонок |
| CREATE INDEX / CREATE TRIGGER | Имя, целевая таблица/view, уникальность/колонки/предикат индекса; имя триггера, BEFORE/AFTER/INSTEAD OF, события, FOR EACH ROW, вызываемая функция |
| GRANT / REVOKE | Явно перечисленные таблицы/view, права (включая списки колонок), получатели (включая PUBLIC) и признак grant option как отдельная операция |
| ALTER TABLE ADD CONSTRAINT | CHECK/FK/PK/UNIQUE/NOT NULL: тип, имя, выражение, ссылки и колонки |

`ddl.py` применяет `ordered_files` отдельного migration manifest, разрешая пути
от его каталога внутри project root, а также DDL внутри одного файла в порядке файла
(ALTER/RENAME/DROP после CREATE в том же файле). mtime не используется. Нет установленного
порядка для межфайлового DDL — `ambiguous`; неподдержанный шаг — `unsupported`, без допуска.
Несколько файлов при установленном порядке не означают неоднозначное определение.
PK, добавленный через ALTER, обновляет `primary_key` и `nullable` колонок; финальное
состояние не заменяется исходным CREATE. Конфликты между файлами проверяются после
применения локальных ALTER/RENAME. Reconstruction по manifest пока поддерживает
табличные CREATE/ALTER/RENAME/DROP/COMMENT; INDEX/TRIGGER/GRANT в таком manifest
остаются явным `unsupported`, хотя их отдельные SQL-операции извлекаются AST.

DDL связывается с объявлением целевой таблицы/view, а не с последним объектом файла.
Для выбранной страницы операции соседних объявлений исключаются. Необработанный
оператор или DDL без соответствующего объявления оставляет блокирующий пробел;
он не присваивается произвольной странице. Пример 13 проверяет отдельные страницы
журнала аудита и таблицы с триггером. GRANT на схемы/functions и ALL TABLES IN SCHEMA
пока создаёт пробел анализа. Regex-путь не подтверждает полноту этих конструкций
и не заменяет обязательную зависимость pglast.

`sql_types.py` разделяет тип назначения и выражения. Доказательства — CREATE/упорядоченный
DDL, явный cast, узкий каталог встроенных выражений (`now`, `count`, `to_date`) и
однозначные ссылки на колонки/параметры. `expression_status` различает `known`, `unknown`
и `not_applicable`. Нельзя заменить доступный тип назначения на null или тип выражения.
Произвольные перегрузки операторов/функций и полная проверка типов требуют БД и не заявлены.

Циклы/exception handlers PL/pgSQL, рекурсивный lineage CTE, wildcard-выходы без развёртки,
неподдержанные AST-узлы, неизвестный search_path и неразобранная динамика создают
`coverage_notes` и блокируют gate. Полная поддержка PostgreSQL/Greenplum не заявлена.
Префикс CKR_GP не устанавливает версию Greenplum. Матрица расширяется только с тестами.

Диалекты CLI — `postgres` и `postgresql`; `greenplum` отклоняется даже при активном
CKR_GP. Случай 11 проверяет правила профиля на PostgreSQL-синтаксисе с неизвестной
версией. Поле `version` не переключает грамматику pglast и не доказывает совместимость
с сервером. Подтверждённые сценарии, тесты отказа и непроверенные конструкции:
[матрица диалектов](../docs/dialect-support.md).

Подтверждённые эффекты вызываемой функции хранятся отдельно от прямых writes.
Разрешение перегрузки по догадке запрещено: несколько кандидатов не дают подтверждённый эффект.
