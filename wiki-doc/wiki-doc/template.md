# Применимость и порядок секций wiki

Это единственная карта применимости для основного агента, writer и validator.
Форматы выходных таблиц определены в связанных блоках и здесь не дублируются.
Файл блока читается только при генерации или проверке его секций.

| Блок | Секции | Когда нужны |
|------|--------|-------------|
| [01](template/01-header-purpose.md) | Заголовок, Назначение | Для каждого документируемого объекта |
| [02](template/02-schema-signature.md) | Схема работы, Сигнатура, Параметры, Ключевые моменты | Сигнатура — для функции/процедуры, включая read-only и без аргументов; схема — при нескольких шагах/ветвлениях; ограничения — если есть |
| [03](template/03-entities.md) | Структура и бизнес-сущности, Справочники | Колонки — для таблиц, view/CTAS, RETURNS TABLE и результатов преобразований; справочники — если подтверждены кодом/описанием |
| [04](template/04-formulas-dependencies.md) | Расчётные формулы, Зависимости, CTE | Формулы/фильтры/агрегация — если есть **в любом типе объекта**; зависимости — для всех объектов (можно явно указать отсутствие); CTE — если есть |
| [05](template/05-dataflow-diagram.md) | Диаграмма потока данных | При двух и более физических источниках или сложном потоке изменений; для простой операции опциональна |
| [06](template/06-misc.md) | Критические даты, Ошибки, Семантика операций, Примеры, Неопределённости, Замечания, Связанные объекты | Даты — при значимых границах/переключении логики; ошибки — при обработчиках; семантика — при изменениях; примеры — если осмысленны; неопределённости — при пробелах; связи — при наличии |

Для функции, которая только читает, проверяй формулы, фильтры, зависимости, результат
и параметры наравне с ETL-функцией. Для view наличие арифметики/CASE включает проверку
формулы; для миграции проверяется переход структуры, а не параметры вызова.

Неприменимую секцию можно опустить. Причину `not_applicable` сохраняет отчёт
валидатора; заполнять страницу пустыми заголовками не нужно.
Если данных не хватает для применимой секции, это **не** not_applicable:
укажи неопределённость, не выдумывая содержание.

Профиль добавляет конкретные предметные проверки только при совпадении проекта
и наличии конструкции. Он не отключает сверку реально существующей формулы/операции
и не задаёт минимальное число замечаний.

Порядок блоков: 01 → 02 → 03 → 04 → 05 → 06, с пропуском неприменимых секций.
На странице сохраняй метаданные происхождения: канонический ключ, пути и хеши
SQL/DDL, ревизию, активный профиль и проверенные ограничения.
