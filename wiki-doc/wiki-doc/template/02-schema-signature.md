# Блок 02 — работа, сигнатура и параметры

Применимость — в [template.md](../template.md).

## Схема работы

Для нескольких шагов или ветвей опиши порядок операций по реестру:
условие выполнения → чтение/преобразование/изменение → результат.
Не превращай ветвление или цикл в безусловную линейную последовательность.
Можно использовать нумерованные шаги, ASCII или Mermaid; каждый фактический оператор
должен иметь покрытие, но не обязан занимать отдельный громоздкий блок.
Бизнес-группы извлекай из кода, а не из количества INSERT.

## Сигнатура и параметры

Вставь точное объявление функции/процедуры без тела: имя, режимы аргументов,
типы, DEFAULT, RETURNS, язык и значимые атрибуты, если они есть.
Применяй к любым routines, включая функции без записи и без аргументов.

Выходная таблица параметров:

| Параметр | Режим | Тип | DEFAULT в сигнатуре | Поведение при спецзначении | Описание |
|----------|-------|-----|---------------------|----------------------------|----------|
| p_start | IN | varchar | отсутствует; вход обязателен | при 'default' — ветвь чтения очереди, если она есть в SQL | Начало периода |
| p_limit | IN | integer | 10 | — | Ограничение результата |

Строки выше иллюстрируют формат; реальные строки берутся только из объявления.
Для отсутствующих аргументов укажи «Параметров нет» вместо фиктивной таблицы.

DEFAULT (или `= expression`, если допустимо диалектом) задаётся в сигнатуре.
Условие `IF p_start = 'default'` не разрешает опустить обязательный аргумент.
OUT не является входным аргументом. Для INOUT/VARIADIC учитывай правила диалекта.
Указанный явно специальный аргумент допустим в примере, если так работает код.

## Ключевые моменты

Отметь существенные особенности: результат, способ загрузки, режим транзакций,
права исполнения, fallback параметров, дедубликацию или ограничения среды.
Включай только обнаруженные особенности, без фиксированного количества пунктов.
