# Блок 03 — структура, сущности и справочники

Применимость — в [template.md](../template.md).

Для таблицы документируй объявленные колонки. Для загрузки сопоставь колонки
цели с выражениями SELECT по позиции и учти колонки, заполняемые DEFAULT.
INSERT без списка колонок и SELECT * разрешай только по подтверждённой структуре.
Для view/CTAS/RETURNS TABLE документируй выходной результат, включая read-only функции.

## Формат структуры

| Колонка | Тип целевой колонки / результата | Тип выражения | Выражение / источник | Описание | Основание |
|---------|---------------------------------|---------------|----------------------|----------|-----------|

Указывай точность/длину и time zone, если они подтверждены. NULL, DEFAULT, ключи
и ограничения можно вынести в отдельную таблицу, чтобы не перегружать строку.
Для описания результата преобразования тип источника не заменяет тип назначения.

- Существующая таблица: тип цели — из её DDL с учётом выбранных миграций.
- View/CTAS: тип результата — из SELECT, когда он однозначно выводится.
- Routine: объявленный тип результата — из RETURNS/OUT; тип выражения — отдельно.
- CREATE TABLE без выражения: «не применимо» для типа выражения.
- Неподтверждённый тип: `unknown` с причиной и ссылкой на неопределённость.
- Тип выражения можно подтвердить явным приведением или правилом диалекта.
  В PostgreSQL `now()` — timestamptz; это не доказывает тип существующей целевой колонки.

Для типов цели и выражения указывай соответствующие основания отдельно.
Описание колонки из комментария атрибутируй. Несоответствие комментария вычислению
не скрывай и не заменяй технический смысл бизнес-догадкой.

## Справочники

Справочник выделяется по подтверждённой роли, а не только по префиксу SPR.
Опиши поля тем же форматом, роль JOIN/фильтра и известные значения.
Значения кодов бери из SQL/seed-данных/документации; DDL без данных не подтверждает
перечень статусов. Очередь обозначай очередью, а не автоматически справочником.

Для промежуточных CTE и временных таблиц укажи область видимости и время жизни.
Объединять технические таблицы в одну бизнес-сущность можно только с объяснением.
